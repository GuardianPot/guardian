# P2-W8 — SMB low-interaction pack

## 1. Purpose

A Windows-flavoured file service that answers SMB negotiation well enough for
enumeration tools to identify it and try, so a probe becomes evidence — while
the product never claims it is a real Windows host.

## 2. Decided

**A Guardian Go emulator with no new dependency** (Product Owner, 2026-09-13),
in `apps/decoys`, standard library only, `FROM scratch`.

**Telemetry follows `P2-W5` section 3**, which is open and blocks
implementation.

**Protocol depth ends at session setup.** Low interaction: the emulator
negotiates, runs the NTLMSSP challenge far enough to learn the claimed user,
domain, and workstation, and refuses the session. There is no tree connect, no
share, and no file. That is enough for `AC-SMB-001` and keeps the attacker-facing
parser to three message types.

## 3. Scope, once `P2-W5` section 3 is decided

1. `apps/decoys/cmd/smb-fileshare`, on 445 (and 139 with the NetBIOS session
   request answered):
   - SMB1 `Negotiate` containing an SMB2 dialect is answered with an SMB2
     `Negotiate` response; pure SMB1 is closed (as a current Windows does).
   - SMB2 `Negotiate`: dialect selection among 2.0.2–3.1.1, a fixed
     server GUID per decoy, persona-consistent capabilities, no signing
     required.
   - SMB2 `SessionSetup` with NTLMSSP `NEGOTIATE` → `CHALLENGE` carrying the
     persona's NetBIOS and DNS names; `AUTHENTICATE` parsed for user, domain,
     and workstation, then `STATUS_LOGON_FAILURE`.
   - Anything else: `STATUS_ACCESS_DENIED` or close.
2. Events: `connection_opened`, `request_received` for negotiate (dialects
   offered, client GUID), `auth_failed` with `domain\user` as identity,
   `connection_closed`. The NTLM response hashes are **not** kept: they are
   crackable credential material and `EV-03` forbids it.
3. **Emulated, and says so** (`AC-SMB-002`): the persona is
   `windows_file_service_host`, the pack's interaction level is `low`, and the
   events carry the pack identity, so the console can render "Windows-flavoured
   SMB emulation" and never an OS claim. Nothing in the evidence asserts a
   Windows version as observed fact.
4. `apps/edge-agent/internal/packs/smb`: the `smb-audit` adapter.
5. Fuzz tests of the NetBIOS framing and the three parsers; a containerd lab
   running `smbclient -L` and `nmap --script smb-protocols` from the attacker
   namespace.

## 4. Security constraints

1. Every length field is checked against the frame before use; frames are
   bounded (NetBIOS length ≤ 65 535 for this pack), NTLMSSP offsets are checked
   against the security buffer. A parser that indexes with an attacker's
   offset is the classic SMB bug, and fuzzing is required, not optional.
2. No NTLM hash, no LM/NT response, no session key retained or emitted.
3. `NET_BIND_SERVICE` only, non-root, read-only root, egress denied.

## 5. Acceptance

| Criterion | Evidence |
|---|---|
| AC-SMB-001 | Lab: `smbclient -L` and an nmap SMB probe yield events with source, target, protocol, and action |
| AC-SMB-002 | Events and pack metadata identify an emulated low-interaction Windows-flavoured service; no OS claim is emitted as fact |

## 6. Non-goals

No shares, no file access, no SMB1 dialect, no signing or encryption, no
Kerberos.

## 7. Deliverables

The emulator, its adapter, parser fuzz tests, the lab, the runbook, and
`security/p2-w8-smb-review.md`.
