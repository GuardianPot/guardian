# P2-W1 — Routed presence driver

## 1. Purpose

Put a decoy's address on the network, take it off again, and never be wrong
about which of those is true.

## 2. What this package is made of

Two halves with very different risk.

**The driver** decides what should happen: which addresses are wanted, whether
each may safely be taken, what to release, and what to report. It holds no
privilege and reaches the host only through a seam.

**The netlink adapter** is what actually adds and removes an address, and it
runs as root inside the `P1-W8` privileged helper. `AGENTS.md` names privileged
networking as a stop-and-ask, and this is squarely that.

The driver is implemented. The adapter is not, and neither is the conflict
probe `AC-ON-004` needs; both are recorded in section 6 as owner decisions.

## 3. Scope

1. `apps/edge-agent/internal/presence`: the reconciler, its `Driver`,
   `ConflictProbe`, and `Reservations` seams, and the reconciliation rules.
2. Reservation persistence, so a restarted agent can release an address a
   previous process applied.
3. Desired-versus-observed reporting per address.

## 4. Non-goals

- **No nftables.** `P2-W2` owns egress, and the agreed order puts it before any
  attacker-facing pack for that reason.
- **No container.** `P2-W3` owns the runtime; an address without a listener is
  still a correct outcome for this package.
- **No scanning.** The conflict probe answers one question about one address the
  operator already chose. It is not discovery, and nothing here enumerates a
  network.

## 5. The rules, and why they are these rules

**An address is taken only after something says it is free.** `AC-ON-004`
requires a deployment onto an address another host answers on to be refused
fail-safe with the existing host unaffected. The reconciler treats "the probe
could not tell me" as a refusal too, because it is not "the address is free".
Taking an address that turns out to belong to a production host is how a
deception product causes the outage it was bought to prevent.

**Removals run before applies.** The Control Plane permits an address to move
between decoys. Applying the new holder first would put a duplicate on the wire.

**A failed apply releases in the same pass.** The acceptance criterion is that a
failed deploy leaves no orphan IP. The window in which one exists is between a
partial apply and the next reconcile, so the release is issued there rather than
deferred.

**An unconfirmed apply is not presence.** A driver that will not say it applied
the address has not applied it. The same rule the decoy observed state follows:
absence of confirmation is never a claim.

**Reservations are persisted.** A restart is a new process with empty memory and
a host still holding every address the old one applied. Without the reservation
set, an address the Control Plane stopped asking for would stay on the interface
until the host went down.

## 6. Blocked on an owner decision

Two capabilities this package needs do not exist, and both are gated by
`AGENTS.md`.

**A privileged address-presence probe.** `AC-ON-004` cannot be satisfied
without one: deciding whether another host answers on an address needs an ARP
probe, which needs a raw socket, which is privileged. The privileged contract in
`proto/guardian/privileged/v1/privileged.proto` has no such operation, and
adding one is both a public-contract change and a privileged-networking change.
Until it exists the reconciler refuses every address, which is the fail-safe
direction and is asserted by test.

**The netlink adapter.** `EnsureAddress` is validated, allowlisted, audited, and
idempotent in the helper today, and its adapter is `UnsupportedAdapter` —
`P1-W8` built the boundary and deliberately left the implementation out. Filling
it is new root-privileged code that mutates host networking.

Neither is written here. The driver treats both absences honestly: an
unsupported host reports `unsupported`, never `present`.

## 7. Acceptance criteria

1. An address another host answers on is refused, and nothing reaches the host.
2. An address whose freedom cannot be established is refused for that reason,
   distinguishably.
3. A failed apply issues a release in the same pass and holds nothing.
4. An unconfirmed or unsupported apply is never reported as present.
5. A restarted reconciler can release what a previous process applied.
6. An address moving between decoys is released before it is taken.
7. `task check` passes.

Criteria 1 through 7 are met by the driver. `AC-ON-004` is met *as a rule the
driver enforces*; proving it against a real segment needs the probe from
section 6.
