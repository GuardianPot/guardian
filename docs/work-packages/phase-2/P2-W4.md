# P2-W4 — Decoy manifest schema

## 1. Purpose

Define what a decoy pack *is*, as a checked contract, so that `P2-W3` has
something to build a runtime from and `P2-W5` through `P2-W8` have something to
fill in.

## 2. Why now

`P2-W15` made the decoy a real record and deliberately gave it nowhere to put a
runtime detail: no image, command, mount, capability, or port field exists in
the API, on the wire, or in the database. Runtime detail is resolved from the
server-side pack index instead, and that index currently carries four rows with
a family, an interaction level, and a null digest.

That is the whole of what Guardian knows about a pack. It is not enough to
start a container with, which is why `P2-W3` is blocked on this.

## 3. Scope

1. `schemas/decoy/v1/decoy-manifest.schema.json`, covering the roadmap's field
   list: type and version, interaction level, ports, network mode requirements,
   privilege and capability requirements, telemetry adapter, health probe,
   resource limits, egress requirements, and persona metadata.
2. A manifest for each of the four `DC-01` families, under `decoys/<pack>/`.
3. A loader and validator in the Control Plane's deception domain, with the two
   named acceptance behaviours as its first-class errors.
4. Consistency between the manifests and `decoys/index.json`, enforced by test
   rather than by review.

## 4. Non-goals

- **No pack implementation.** No image, no adapter, no attacker-facing
  behaviour. `P2-W5` through `P2-W8` do that.
- **No runtime.** Nothing here starts, stops, or inspects a container.
  `P2-W3` does that, and this exists so it can.
- **No signature verification.** `AC-SEC-004` is the Phase 5 gate. A manifest
  is a checked declaration, not a verified artefact.
- **No API or wire change.** The decoy contract stays exactly as `P2-W15` left
  it. A manifest is resolved server-side and never travels as a decoy field.
- **`pack_digest` stays null.** The contract says it is null "until `P2-W4`
  defines a manifest **and a pack exists to hash**". This satisfies the first
  condition only. Hashing the manifest and calling it the pack digest would
  assert an artefact identity nothing has verified — the same failure the field
  was written to avoid.

## 5. Security constraints

1. **The privilege vocabulary is closed and small.** A manifest may request
   only what `ADR 0009` and the `P0-W6` review already established as the decoy
   runtime baseline. Anything else is rejected at load, not filtered out:
   a manifest asking for something Guardian will not grant is a manifest
   nobody should be running, and silently dropping the request would leave the
   pack author believing they had it.
2. **There is no escape hatch.** No free-form capability string, no raw OCI
   spec passthrough, no host path, no runtime socket, and no field in which one
   could be expressed. The schema forbids unknown properties everywhere.
3. **Egress is deny-by-default.** `AC-SEC-003` requires the default policy to
   block a forbidden external destination. A manifest declares what it needs;
   it cannot declare "everything", and the absence of a declaration means
   nothing is allowed rather than everything.
4. **A version mismatch is explicit and fatal.** A manifest whose schema
   version this build does not implement is refused with a distinguishable
   error. It is never coerced, partially read, or treated as the current
   version.
5. **Persona metadata is content, not code.** It carries bounded text for a
   pack to present. It cannot name a file, a path, a template engine, or a
   command.

## 6. Acceptance criteria

1. A manifest requesting a privilege outside the closed set is rejected, and
   the rejection names the privilege class rather than failing generically.
2. A manifest carrying an unknown or absent schema version is rejected with an
   error distinguishable from every other validation failure.
3. Each of the four `DC-01` families has a manifest that validates.
4. Every manifest agrees with `decoys/index.json` on pack, version, family, and
   interaction level, and `INT-01` holds for each.
5. The schema forbids unknown properties at every level.
6. `task check` passes.

## 7. Deliverables

The schema, four manifests, the Control Plane loader and its tests, the
contract-fixture update, and a security review of the privilege and egress
vocabularies.
