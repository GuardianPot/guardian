# P2-W15 — Decoy domain, lifecycle contract, and management surface

## 1. Purpose

Give Guardian a decoy that exists. Today the word appears in three places and
means nothing in any of them: a `PlaceholderDecoy` struct in the
reconciliation snapshot that is always written as an empty slice, a
`deception` module whose `Start` returns `nil`, and a `decoys/README.md` that
says implementations arrive later.

This package makes a decoy a real object — recorded, addressed, versioned,
reconciled to an Edge, and reported back — and defines the contract the
console reads to show it.

## 2. Why now

`UX-06` approves a decoy management minimum and the Phase 2 exit gate requires
four decoy families visible in the console. `WCX-11` is written, approved, and
blocked: its section 4 says plainly that `P2-W15` and the Phase 2 decoy
backend must be accepted first, because it "consumes a contract it does not
create". Nothing in the repository creates that contract.

The four runtime packages — `P2-W5` through `P2-W8` — each produce a decoy
family. Without a domain to attach them to, each would invent its own record
shape, and the console would meet four different notions of what a decoy is.

## 3. Inputs and decisions

- `UX-06` — the approved management minimum: list, persona/type, IP/zone,
  health, version, last interaction, enable/disable, deploy/remove, update
  state. This package supplies every field that minimum names; `WCX-11`
  renders them.
- `UX-08` — no topology map. A zone and decoy list is sufficient, so the
  contract is a list contract and carries no graph.
- `DC-01` — four families in the MVP.
- `DC-11` — a curated persona set: Linux admin/server, internal admin web
  app, database server, Windows file/service host. Persona is a closed
  enumeration in the contract, not free text, and no generative persona
  builder exists.
- `DC-12` — every pack carries a version and digest and is updatable from the
  Control Plane through desired state.
- `INT-01` — interaction level is part of a decoy's identity: low for HTTP and
  SMB, medium for SSH.
- `SEC-06` — a revoked device's decoys are reported as unmanaged, never as
  healthy and never as absent.
- `OPS-02`, `ON-05`, `SA-11`, `CP-06`.

## 4. Dependencies

`P1-W3` for the environment and zone domain a decoy is placed into, `P1-W5`
for the device channel that carries desired state, `P1-W6` for the reconciler
that publishes it, and `P1-W9` for the health condition model this package
extends to decoys.

`P2-W4` is an integration dependency: this package stores and transmits a
manifest reference and version, and `P2-W4` defines what a manifest contains.
The two can be built in either order provided the manifest identifier and
version fields are agreed first; this package treats a manifest as an opaque
`(pack, version, digest)` triple and never parses one.

`P2-W3` and `P2-W14` are integration dependencies for observed state. This
package defines how observed state is reported and stored; those packages
produce it. **Until they land, every decoy's observed state is `unknown`, and
that is a correct and required outcome rather than a gap** — see section 8.

## 5. Scope

1. The decoy record in the Control Plane: identity, environment, zone,
   address, persona, family, interaction level, pack version and digest,
   desired lifecycle state, and timestamps.
2. The REST surface `WCX-11` consumes: list, read, create, update, remove,
   enable, disable.
3. Desired-state transport: replace `PlaceholderDecoy` with the real desired
   object and carry it to the Edge over the existing device channel.
4. Observed-state reporting: the Edge reports each decoy's runtime state and
   last interaction, and the Control Plane stores it beside — never merged
   into — the desired state.
5. The decoy health condition set, following the `P1-W9` condition model.
6. Audit events for every lifecycle transition.
7. The Edge-side decoy component that receives desired state and reports
   observed state, with a null runtime until `P2-W3` supplies a real one.

## 6. Non-goals

- **No decoy pack, adapter, image, or attacker-facing behaviour.** `P2-W5`
  through `P2-W8` own those. `decoys/**` is allowed here only to record the
  pack index this package reads; no pack is implemented.
- No containerd lifecycle. `P2-W3` owns it; this package calls a runtime
  interface and ships a null implementation.
- No functional health probing. `P2-W14` owns it; this package defines the
  condition types it will populate.
- No console work. `apps/web-console/src/**` is forbidden; `WCX-11` renders
  this contract.
- No incident, evidence, or event intelligence. A decoy's `last_interaction`
  is a timestamp, not a finding.
- No synthetic credential. `P2-W9` owns it.
- No topology map, no graphical placement, no AI-assisted placement.
- No signature enforcement. `AC-SEC-004` is a Phase 5 gate; this package
  records a digest and does not verify one.

## 7. Allowed paths

Only the paths in frontmatter. Two exclusions are deliberate:
`internal/devicepki/**` and `internal/privileged/**` are forbidden because a
decoy must never be able to reach device identity or privileged operations,
and a package that cannot edit those files cannot accidentally connect them.

## 8. Security constraints

1. **A decoy never holds device identity.** The decoy record carries no key,
   certificate, or credential, and the Edge component that manages decoys has
   no path to the device key material. A source-level check asserts the decoy
   package imports neither `devicepki` nor `privileged`.
2. **Desired and observed state are stored separately and are never merged.**
   An operator asked for something; the network reports something. Collapsing
   the two into one field is how a console ends up claiming a decoy is running
   because someone once asked for it.
3. **Observed state defaults to `unknown`, never to healthy and never to
   absent.** A decoy whose Edge has not reported is in an unknown state. This
   is the `P1-W9` rule applied to decoys, and it is the single most important
   constraint here: a deception product that shows a decoy as deployed when
   nothing confirmed it is lying about coverage.
4. **A revoked or disabled device's decoys are reported as unmanaged**
   (`SEC-06`). Not healthy, not removed, not silently absent from the list.
   An operator must be able to see that a decoy exists and that Guardian has
   lost the ability to manage it.
5. **Persona and family are closed enumerations** validated against the
   contract. They reach the console as tokens, never as free text, so the
   console never renders an unbounded backend string as a category.
6. **Every attacker-influenceable field is bounded and marked.** A decoy's
   display name is operator-supplied and round-trips through the API; a
   persona label is not. The contract states which fields the console must
   treat as untrusted.
7. **The address a decoy claims is validated against its zone.** A decoy
   placed at an address outside its zone's CIDR is rejected by the Control
   Plane, so a misconfiguration cannot silently produce a decoy that answers
   on a production address.
8. **Removal is not deletion of history.** A removed decoy leaves an audit
   trail and its interactions remain attributable. The record may leave the
   active list; the audit events do not.
9. No decoy configuration field accepts a container image reference, command,
   mount, or capability from the API. Those come from the manifest, which is
   selected by `(pack, version)` from a server-side index.

## 9. Implementation requirements

### 9.1 The decoy record

| Field | Notes |
|---|---|
| `decoy_id` | UUIDv7, Control Plane issued |
| `environment_id`, `zone_id` | Placement. The zone bounds the address |
| `display_name` | Operator-supplied, bounded, **untrusted** to the console |
| `family` | `ssh`, `http`, `postgres`, `smb` — closed, per `DC-01` |
| `persona` | Closed enumeration per `DC-11` |
| `interaction_level` | `low` or `medium` per `INT-01` |
| `address` | The IPv4 address inside the zone the decoy answers on |
| `pack`, `pack_version`, `pack_digest` | Per `DC-12`. Opaque here |
| `desired_state` | `deployed`, `disabled`, `removed` |
| `revision` | Optimistic concurrency, following the zone pattern |
| `created_at`, `updated_at` | |

Observed state is a separate record keyed by `decoy_id`, carrying
`observed_state`, `last_interaction_at`, `reported_at`, the reporting device,
and the condition set from 9.4. It is written only by the device channel and
is never writable through the REST surface.

### 9.2 REST surface

Following the existing environment and zone shape, including `If-Match`
revision handling on update and remove.

| Operation | Endpoint |
|---|---|
| List decoys in an environment | `GET /v1/environments/{environmentId}/decoys` |
| Create | `POST /v1/environments/{environmentId}/decoys` |
| Read | `GET /v1/environments/{environmentId}/decoys/{decoyId}` |
| Update configuration | `PATCH /v1/environments/{environmentId}/decoys/{decoyId}` |
| Remove | `DELETE /v1/environments/{environmentId}/decoys/{decoyId}` |
| Enable | `POST /v1/environments/{environmentId}/decoys/{decoyId}/enable` |
| Disable | `POST /v1/environments/{environmentId}/decoys/{decoyId}/disable` |

Every response carries desired and observed state as separate objects. The
list is bounded at 200 following the existing page conventions.

Enable and disable are separate operations rather than a `PATCH` field
because `WC-D16` assigns them confirmation levels, and a level is assigned to
an operation rather than to a field within one.

### 9.3 Desired-state transport

`reconciliation.PlaceholderDecoy` is replaced by the real desired object and
the protobuf message alongside it. The reconciler publishes a decoy revision
the same way it publishes zones; the Edge applies it the same way.

`MaxPlaceholderDecoys = 64` becomes the decoy bound and keeps its value, so
the device-channel message-size guarantee is unchanged.

### 9.4 Health conditions

Following the `P1-W9` structured condition model — stable type, `True`/
`False`/`Unknown` status, stable reason, bounded message, observed revision,
transition time — with the condition set `P2-W14` will populate:

`runtime_healthy`, `address_applied`, `port_responding`,
`telemetry_reporting`, `policy_applied`, `version_matches_desired`.

Every one is `Unknown` until something reports it. `P2-W14`'s acceptance is
that killing the process, removing the IP, and breaking telemetry each yield a
*distinct* degraded state, which is only possible if the conditions are
separate from the start.

### 9.5 Audit

New actions in the closed vocabulary, each with its migration row:
`decoy.created`, `decoy.updated`, `decoy.removed`, `decoy.enabled`,
`decoy.disabled`, all against object type `decoy`.

### 9.6 Edge component

A decoy component that receives desired state, asks a `Runtime` interface to
converge, and reports observed state. This package ships the null runtime:
it accepts desired state, converges nothing, and reports `unknown`. `P2-W3`
replaces it.

This is not a stub for convenience. It is the shape that makes `P2-W3`
replaceable, and it is what lets the console and the contract be exercised
end to end before any container exists.

## 10. Required tests

### 10.1 Unit and integration

1. A decoy address outside its zone CIDR is rejected.
2. Family, persona, and interaction level outside the enumerations are
   rejected.
3. A decoy with no observed report reads `unknown`, never healthy or absent.
4. Desired and observed state are separately addressable; no read path
   returns one in place of the other.
5. A revoked device's decoys report unmanaged and remain listed (`SEC-06`).
6. `If-Match` conflicts on update and remove behave as the zone domain's do.
7. Every lifecycle transition emits its audit event, and the vocabulary
   migration accepts each new pair.
8. The desired-state snapshot carries decoys and stays inside the
   device-channel size bound at the 64-decoy limit.
9. A source-level check asserts the decoy packages import neither `devicepki`
   nor `privileged` (`AC-SEC-002` in the direction this package can prove).
10. Removing a decoy leaves its audit trail intact.

### 10.2 Contract

1. The generated console types compile against the new paths.
2. No existing operation's request, response, or semantics change.

### 10.3 Deferred to integration dependencies

Functional health (`AC-ON-006`), real deployment (`AC-ON-005`), and runtime
isolation (`AC-SEC-002` in the runtime direction) are proven by `P2-W3` and
`P2-W14`. This package's own acceptance is that their results have somewhere
truthful to land.

## 11. Acceptance criteria and Definition of Done

1. A decoy can be created, configured, enabled, disabled, and removed through
   the API, with each transition audited.
2. Desired state reaches the Edge over the existing device channel and the
   Edge reports observed state back.
3. Observed state is `unknown` until reported, and no read path presents an
   unreported decoy as deployed or healthy.
4. A revoked device's decoys are listed as unmanaged.
5. `WCX-11` can be unblocked: every `UX-06` field exists in the contract.
6. `task check` and the decoy integration suite pass.
7. The security review is recorded.

## 12. Stop and escalate

Stop and request owner review if any of the following occurs:

- the four families cannot share one record shape without a per-family
  configuration blob, which would push family-specific structure into the
  console and reopen `UX-06`;
- desired and observed state cannot be kept separate through the device
  channel without a protocol change beyond adding the decoy object;
- placement validation needs network truth the Control Plane does not have,
  which would move address assignment to the Edge and reopen `P2-W1`;
- the 64-decoy bound cannot hold the real desired object inside the
  device-channel message limit;
- a decoy record turns out to need credential or key material, which would
  contradict section 8.1 and require a change proposal.

## 13. Deliverables

The decoy domain and storage, the REST surface, the desired-state object and
its transport, observed-state reporting and storage, the health condition set,
the audit vocabulary and its migration, the Edge decoy component with a null
runtime, the integration suite, the runbook section, and
`security/p2-w15-decoy-domain-review.md`.
