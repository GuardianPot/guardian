# P2-W7 — PostgreSQL pack

## 1. Purpose

A low-interaction PostgreSQL server: enough of the wire protocol that scanners
and clients identify it and attempt to authenticate, so the attempt — and above
all the use of a planted credential — becomes evidence.

## 2. Decided

**A Guardian Go emulator with no new dependency** (Product Owner, 2026-09-13),
in `apps/decoys` beside `P2-W6`, standard library only, `FROM scratch`.

**Telemetry follows `P2-W5` section 3**, which is open and blocks
implementation.

**The password travels in cleartext on purpose.** The emulator requests
`AuthenticationCleartextPassword`, not SCRAM. SCRAM would never reveal the
password to the server, so a planted credential could not be recognised;
cleartext is what a misconfigured real server does, and a client that refuses it
still produces `AC-PG-001` and `AC-PG-002` evidence.

**Recognition in the emulator, not at the Edge.** Unlike Cowrie, this is
Guardian code, so the password is compared with `syntheticcred.Set.Recognize`
where it arrives and is cleared before anything is written; only the id leaves.
That puts the entries in the decoy, which needs the `synthetic_credentials`
array delivered into the container — part of the `P2-W5` section 3 decision.
The alternative, sending the typed password to the Edge for recognition, is
refused: it would put a secret on the telemetry path.

## 3. Scope, once `P2-W5` section 3 is decided

1. `apps/decoys/cmd/postgres-service`, a wire-protocol v3 state machine:
   - `SSLRequest` answered `N`; `GSSENCRequest` answered `N`; `CancelRequest`
     closed.
   - `StartupMessage` parsed with a length bound (10 000 bytes, as upstream),
     a parameter count bound, and `user`/`database`/`application_name`
     captured bounded (`AC-PG-001`, `AC-PG-002`).
   - `AuthenticationCleartextPassword`, then `PasswordMessage` bounded; the
     password is recognised, cleared, and the session ends with
     `28P01 password authentication failed` — a planted credential fails too,
     since the low-interaction pack has no query engine.
   - Any other message or an out-of-state message closes the connection.
2. Events: `connection_opened`, `auth_attempt` → `auth_failed` with
   `auth.identity` (user) and the database in bounded metadata, and
   `auth.synthetic_credential_id` on a match (`AC-PG-003`),
   `connection_closed`.
3. `apps/edge-agent/internal/packs/postgres`: the `postgres-wire` adapter.
4. Fuzz tests of the message parser; a containerd lab running `psql` from the
   attacker namespace with a wrong password, the planted one, and a raw
   malformed startup packet.

## 4. Security constraints

1. The parser reads a length, checks it against the bound, then allocates —
   never the reverse. Every read has a deadline; connections are capped.
2. No query execution: there is no query path at all in the low-interaction
   pack. The manifest's `query_executed` action stays unused until an owner
   decides a medium-interaction PostgreSQL pack exists.
3. The password is not logged, not in an error, and not in any event. Tests
   assert it with the planted secret and a guessed one.
4. No capability (5432 needs none), non-root, read-only root, egress denied.

## 5. Acceptance

| Criterion | Evidence |
|---|---|
| AC-PG-001 | Lab: a `psql` connection and a raw startup packet each yield `connection_opened` |
| AC-PG-002 | Lab: user, database, and `auth_failed` captured; the password is absent from every output |
| AC-PG-003 | Lab: the planted credential yields `auth.synthetic_credential_id`; a guessed password does not |

## 6. Non-goals

No SCRAM or MD5 authentication, no query emulation, no TLS.

## 7. Deliverables

The emulator, its adapter, parser fuzz tests, the lab, the runbook, and
`security/p2-w7-postgres-review.md`.
