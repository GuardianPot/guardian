# P2-W6 — HTTP/Admin pack

## 1. Purpose

A low-interaction fake internal admin console: it answers like a real one,
records what was asked of it, and executes nothing an attacker sends.

## 2. Decided

**A Guardian Go emulator with no new dependency** (Product Owner, 2026-09-13).
Standard library `net/http` only. It shares a module with the `P2-W7` and
`P2-W8` emulators, `apps/decoys`, whose `go.mod` has no requirements, and the
image is `FROM scratch` with one static binary, so the pack adds neither a Go
dependency nor a base image.

**Telemetry follows `P2-W5` section 3**, which is open and blocks
implementation. The emulator writes canonical `P2-W10` events; how they leave
the decoy is that decision.

## 3. Scope, once `P2-W5` section 3 is decided

1. `apps/decoys/cmd/http-admin`: a server with a fixed route table compiled in —
   a landing page, a login form, a handful of plausible admin paths — rendered
   from Go string constants. No template engine reading files, no file serving
   from disk, no reflection of request content into a response.
2. **Request capture** (`AC-HTTP-001`): method, path, query, source, and a
   closed allowlist of headers (`Host`, `User-Agent`, `Referer`,
   `Content-Type`, `Content-Length`, `X-Forwarded-For`). `Authorization` and
   `Cookie` are never captured as values; their presence is.
3. **Fake login** (`AC-HTTP-002`): a POST to the login path always fails with a
   generic message after a fixed delay and yields `auth_failed` with the
   username. The password is dropped at parse time; an `http_basic` synthetic
   credential is recognised with `syntheticcred` if the Edge carries entries.
4. **Bodies are bounded** (`AC-HTTP-004`): `http.MaxBytesReader` at the capture
   limit, header and URL size limits on the server, read and write timeouts, a
   cap on concurrent connections. Over the limit, the request is answered with
   `413` and the event records `truncated`; the service keeps running.
5. **XSS is data** (`AC-HTTP-003`): the emulator never echoes request content,
   and every captured string is carried as an escaped JSON string. The console
   side of the contract is `WCX`'s; this package provides the fixture payloads.
6. `apps/edge-agent/internal/packs/http`: the `http-access` adapter, validating
   the emulator's events against the envelope and the pack's own bounds.
7. A containerd lab: the image runs through `P2-W3`, and a client in the
   attacker namespace sends GET, POST, login, an XSS payload, and an oversized
   body.

## 4. Security constraints

1. No server-side execution path: no `os/exec`, no `plugin`, no template
   parsing of anything but compiled-in constants, no filesystem read after
   start. A boundary test in `apps/decoys` enforces the import set.
2. Non-root, read-only root, no capability except `NET_BIND_SERVICE`, egress
   denied by the `P2-W3` policy.
3. Slowloris and flood behaviour bounded by timeouts and a connection cap; the
   emulator degrades by refusing, not by growing.
4. No production secret; persona text is fixture content.

## 5. Acceptance

| Criterion | Evidence |
|---|---|
| AC-HTTP-001 | Lab: GET and POST produce `request_received` with source, path, method, allowlisted headers |
| AC-HTTP-002 | Lab: login POST yields `auth_failed` with username and no password |
| AC-HTTP-003 | Unit and lab: script payloads in path, header, and body survive only as escaped data; nothing is reflected |
| AC-HTTP-004 | Unit and lab: an over-limit body is refused or truncated and marked; the server keeps answering |

## 6. Non-goals

No real authentication, no session state beyond one request, no file upload
storage (`P2-W13`), no console rendering.

## 7. Deliverables

The emulator, its adapter, fuzz tests of request handling, the lab, the
runbook, and `security/p2-w6-http-admin-review.md`.
