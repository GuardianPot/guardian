# P2-W9 — Synthetic credential domain

## 1. Purpose

Plant credentials whose only value is that using one is evidence.

## 2. The inversion, and its one hard limit

Everywhere else in this system a credential is something to protect. Here it is
bait: deliberately discoverable, deliberately worthless, and valuable precisely
because nobody with a legitimate reason would ever type it.

That inverts the handling in one direction only. It is fine for an attacker to
find one. It is not fine for one to work anywhere real, and it is not fine for
Guardian to keep the plaintext after the operator has planted it.

## 3. Scope

`apps/control-plane/internal/credential`: generation, the hash-only stored
form, association with a decoy, the placement workflow, matching, and the
lifecycle `pending → placed → triggered → revoked`.

## 4. The decisions worth arguing about

**The secret exists exactly once.** `New` returns it; nothing stores it. The
`Credential` struct has no plaintext field, so it cannot reach a log, a query
result, or a console by accident. The acceptance criterion — the UI must not
reveal a reusable secret after the intended workflow — is therefore a property
of the type rather than of the screen rendering it.

**Every secret is marked `gdn-decoy-`.** A deliberate trade, recorded in full
in the package comment and the security review. It tells an attacker who has
found one that they are in a honeypot; it also tells anyone finding one in a
paste, a log, or a production password manager that it grants nothing. The
second matters more, because it arrives *before* the credential is typed and the
tell arrives after — by which point the evidence already exists.

**A credential nobody planted is not live.** `pending` sits between minting and
the operator confirming placement. Counting an unplanted credential as live
would overstate coverage, which is the failure this product exists not to make.

**Triggering is idempotent.** An attacker returning to a decoy reports the same
credential again; the first use is what an investigator needs. Overwriting the
timestamp would move "first seen" forward on every visit.

**Revoking stops new evidence and erases none.** `CS-06` forbids silent
deletion: a credential somebody used stays one somebody used.

**Strict base64.** Found by a test. A lenient decoder accepts several textual
spellings of the same 16 bytes, because the final character of a 22-character
encoding carries spare bits. One credential must have exactly one spelling, or
"the attacker typed the value we planted" stops being a precise claim.

## 5. Blocked on an owner decision

**How the recognition material reaches the decoy.** A decoy has to compare what
an attacker typed against the planted hash, and `P2-W15` deliberately gave the
decoy desired object nowhere to put a credential — no field exists in the API,
on the wire, or in the database.

Getting the hash to the Edge therefore needs either a desired-state field or a
separate fetch, and both are public-contract changes (`openapi/`, `proto/`).
That is a stop-and-ask under `AGENTS.md`, and this package does not make it.

Until it is answered the domain is complete and unreachable from a decoy: it
mints, stores, places, matches, and expires credentials, and nothing yet asks it
to. `auth.synthetic_credential_id` in the `P2-W10` envelope is the field a
triggered match will populate.

**No REST surface and no console screen.** Both follow the same decision, since
the placement workflow needs an API to show the one-time secret through.

## 6. Non-goals

- **No pack integration.** `P2-W5` (SSH) and `P2-W7` (PostgreSQL) present the
  credentials and recognise them; this defines what one is.
- **No storage.** No table and no migration yet; the shape is settled first
  because the delivery decision in section 5 may change what is stored.
- **No automatic placement.** The roadmap says manual pilot placement, and an
  automated planter that wrote into real systems would be the single most
  dangerous component in the product.
