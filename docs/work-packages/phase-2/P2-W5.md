# P2-W5 — SSH/Cowrie pack

## 1. Purpose

The first decoy family that answers an attacker: a medium-interaction SSH
server whose every login, command, and session reaches Guardian as canonical
evidence, and which recognises a planted credential.

## 2. Decided

**Upstream Cowrie, not a Guardian SSH server** (Product Owner, 2026-09-13;
`DR-06`, ADR 0011). Cowrie is the only third-party component Phase 2 adds. It is
already pinned and exercised by the `P0-W7` fixture:
`cowrie/cowrie:3.0.12@sha256:3e4ce755…`, upstream `ced855a5…`, BSD-3-Clause
(`deploy/cowrie/PROVENANCE.md`).

**A Guardian wrapper image, not configuration at run time.** Cowrie needs
configuration: listen on 22 rather than 2222, a persona hostname and banner,
JSON logging to the telemetry directory, and a user database. `DR-05` forbids
arbitrary environment or shell injection into decoy configuration, and the
workload definition deliberately has no environment, command, or mount field
(`P2-W3`). So the configuration is baked into a Guardian image built `FROM` the
pinned digest, containing only Cowrie's own configuration files — no added
package, no added binary. The wrapper image is itself digest-pinned in the
workload definition. Promotion of the upstream digest repeats the `P0-W7`
provenance checks.

**Recognition happens at the Edge, not in Cowrie.** Cowrie compares plaintext
against its user database and cannot compare against a hash. Its user database
accepts any password for the persona accounts, so an attacker is let into the
fake shell (which is the medium-interaction evidence `AC-SSH-004` needs), and the
Edge's `cowrie-json` adapter decides whether the password was a planted one with
`syntheticcred.Set.Recognize` (`P2-W9` section 5). A match fills
`auth.synthetic_credential_id`.

## 3. Open — the telemetry handoff (blocks implementation)

Cowrie writes `cowrie.json` into the decoy's `/var/log/guardian` tmpfs
(`P2-W3`). The unprivileged Edge Agent cannot read it: the tmpfs exists only in
the decoy's mount namespace, and `decoyMounts` structurally admits no host path.
Every way across changes a trust boundary or a public contract, so this is the
Product Owner's decision:

- **A. The helper reads, the Edge Agent normalises.** The privileged helper
  tails `/proc/<task-pid>/root/var/log/guardian/<file>` with the same
  no-follow, bounded reading as a workload definition, and streams bounded
  lines to the Edge Agent over a new typed operation. The decoy gets nothing
  new. Costs: a `proto/` addition, and the root process reads
  attacker-authored bytes (bounded, never parsed there).
- **B. A per-decoy host directory, bind-mounted.** The helper creates
  `/run/guardian-edge/decoys/<workload-id>/` owned by the decoy's uid, bounded
  by a size-limited tmpfs, and mounts it at `/var/log/guardian`; the Edge Agent
  reads it. No `proto/` change. Costs: the first host path in a decoy's mounts,
  the property `AC-SEC-002` currently gets structurally, and a directory an
  attacker who controls the decoy can fill or race.
- **C. A per-decoy event socket (`DR-04` native path).** As B, but a Unix
  socket the Edge Agent owns rather than a directory. Natural for Guardian's
  own emulators (`P2-W6`..`P2-W8`); Cowrie still needs a log path, so this is
  C for native packs plus A or B for Cowrie. Costs: a Protobuf event contract
  in `proto/`, and a host path into the decoy, distinct from the management
  socket `SEC-03` forbids.

The recommendation is **A for every pack**. It keeps the decoy with no host
path at all; the one new privileged operation is read-only and bounded. The
emulators then write canonical JSON lines to the same directory, which is a
narrower reading of `DR-04`'s typed contract (typed by the `P2-W10` schema
rather than by Protobuf) and needs the same approval.

## 4. Scope, once section 3 is decided

1. `decoys/ssh-cowrie/`: the wrapper image definition (configuration files and
   a `Containerfile`), the persona accounts, and a build task that produces a
   digest a workload definition can pin.
2. `apps/edge-agent/internal/packs/cowrie`: the `cowrie-json` adapter, mapping
   `session.connect` → `connection_opened`, `login.failed`/`login.success` →
   `auth_failed`/`auth_succeeded` with `auth.identity`, `command.input` →
   `command_executed`, `session.closed` → `connection_closed`, and
   `log.closed` → `session_transcript` with a bounded `raw_ref`. Anything else
   is dropped with a reason, not guessed at.
3. **The password never survives the adapter.** It is recognised and cleared
   before the event exists. A line the adapter cannot parse is quarantined with
   `password` redacted, which needs a pre-quarantine redaction seam in
   `normalize` — the residual risk recorded in the `P2-W9` review.
4. The session transcript (`ttylog`) is bounded and referenced, never inlined;
   storage is `P2-W13`'s.
5. A containerd lab, extending `privileged:containerd`: the wrapper image runs
   through the `P2-W3` runtime with its holder and egress policy, an SSH client
   in the attacker namespace logs in with a wrong password, a guessed
   password, and the planted one, runs commands including a hostile payload,
   and the resulting canonical events are asserted.

## 5. Security constraints

1. The image carries no production secret (`SEC-02`): persona accounts and
   their files are fixtures, checked by the secret scanner.
2. Cowrie's own egress features (proxy mode, `wget`/`curl` download,
   output plugins that send) are disabled in configuration **and** blocked by
   the egress policy. Configuration alone is not a control.
3. The decoy runs as the workload's non-root uid with `NET_BIND_SERVICE` only,
   read-only root, and the `P2-W3` seccomp profile.
4. Command text is `untrusted-attacker-input`: bounded, carried as data, never
   a field a renderer or AI policy treats as instruction (`AC-SSH-005`).
5. No offered password in an event, a log line of the Edge Agent, or a
   quarantine record. Tests assert it with the planted secret and a guessed
   one.

## 6. Acceptance

| Criterion | Evidence |
|---|---|
| AC-SSH-001 | Lab: connect from the attacker namespace yields `connection_opened` with source, decoy, time, session, protocol |
| AC-SSH-002 | Lab: wrong password yields `auth_failed` with identity; the password is absent from every output |
| AC-SSH-003 | Lab: the planted credential yields `auth.synthetic_credential_id`; a guessed password does not |
| AC-SSH-004 | Lab: commands appear as ordered `command_executed` events sharing the session id |
| AC-SSH-005 | Lab and unit: an XSS and prompt-injection payload is preserved as bounded data only |
| No production secret | Secret scan of the wrapper image context; review |

## 7. Non-goals

- No spool or upload (`P2-W12`), no blob storage (`P2-W13`), no functional
  health beyond the manifest's `tcp_connect` probe (`P2-W14`).
- No Cowrie high-interaction or proxy mode, no file download capture.
- No console rendering (`WCX` packages).

## 8. Deliverables

Wrapper image and build task, the `cowrie-json` adapter with fuzz and hostile
input tests, the redaction seam, the lab, the runbook, and
`security/p2-w5-ssh-cowrie-review.md`.
