# P1-G1 — Align Control Plane package boundaries

## 1. Purpose

Align the accepted P1-W1 Control Plane shell with the canonical package roots
already authorized for P1-W2 through P1-W10, without changing product or
runtime behavior.

## 2. Why now

P1-W1 placed persistence, HTTP, and domain shells under `internal/database`,
`internal/httpapi`, and `internal/modules`. Downstream packages authorize
`internal/storage`, `internal/api`, and domain-root paths. Continuing without
alignment would require repeated scope amendments or unconnected duplicate
packages.

## 3. Inputs and decisions

- Product Owner approval of F1-A on 2026-08-23.
- CP-02 domain-oriented modular-monolith boundaries.
- WP-09 isolated worktree and WP-10 stop/escalate behavior.
- Development policy rejects compatibility shims and duplicate legacy paths.

## 4. Dependencies

P1-W1 is merged and accepted. P1-G1 is a hard dependency of P1-W10.

## 5. Scope

- Move PostgreSQL ownership from `internal/database` to `internal/storage`.
- Move the HTTP server from `internal/httpapi` to `internal/api` and combine it
  with the existing API lifecycle shell.
- Move every domain lifecycle shell from `internal/modules/<domain>` to
  `internal/<domain>`.
- Update app/CLI wiring, sqlc paths, generated code, boundary tests, Taskfile,
  and the existing Control Plane integration fixture.
- Record the downstream dependency and canonical package map.

## 6. Non-goals

- New schema, migration, endpoint, authorization rule, dependency, or product
  behavior.
- Audit-model implementation, authentication, environment behavior, or Edge
  changes.
- Legacy import aliases, forwarding packages, or dual directory structures.

## 7. Allowed paths

Only the exact source, destination, wiring, test, task, and package-document
paths listed in frontmatter.

## 8. Security constraints

The database transaction boundary, explicit migration command, health response
surface, HTTP limits, OpenTelemetry instrumentation, and module isolation must
remain equivalent. No credential, privilege, network, or trust-boundary change
is allowed.

## 9. Implementation requirements

- Perform one atomic structural move; update every in-repository consumer.
- Regenerate sqlc output only at `internal/storage/dbgen`.
- Remove the old `database`, `httpapi`, and `modules` trees completely.
- Preserve migration SQL and query SQL content byte-for-byte.
- Preserve liveness/readiness behavior and lifecycle order.
- Enforce that domain packages cannot directly import PostgreSQL or storage
  implementation packages.

## 10. Required tests

- old-path and stale-import residue scan;
- migration/query content hash comparison before and after the move;
- generated sqlc freshness and module-boundary tests;
- `GOWORK=off go -C apps/control-plane vet ./...`;
- `GOWORK=off go -C apps/control-plane test ./...`;
- `bash tests/integration/control-plane/run.sh`;
- `task validate` and `git diff --check`.

## 11. Acceptance criteria

- Canonical destination paths own all moved behavior and old paths are absent.
- The same migration version, SQL, health responses, lifecycle order,
  transaction behavior, and restart evidence pass.
- P1-W10 can implement entirely inside its approved `allowed_paths`.
- No compatibility layer or duplicate package remains.

## 12. Evidence required

Rename/path manifest, before/after SQL hashes, stale-path scan, generated-code
freshness, full local validation, green CI, and owner/security review.

## 13. Stop and escalate

Stop for any schema, endpoint, authorization, transaction, lifecycle, trust,
privilege, or accepted behavior change. Such a change requires a separate
owner-reviewed package or change proposal.

## 14. Deliverables

Canonical Control Plane package roots, updated wiring/tooling/tests, and the
documented dependency that unblocks P1-W10 after acceptance.

## 15. Implementation evidence — 2026-08-23

- The branch is based on accepted P1-W7 merge commit `5f6b7d5` and changes 32
  paths, all inside this package's `allowed_paths`.
- `internal/database`, `internal/httpapi`, and `internal/modules` are absent;
  the repository code/task/integration residue scan found no old-path import or
  command reference.
- Migration SQL remained byte-identical at SHA-256
  `aa2b995d9d523b06ba3f87d05fd38bf82b87a8b65279a97d23ca330ae96b2b5f`.
- Query SQL remained byte-identical at SHA-256
  `3cd93ca9b0ffb3521be6931be30c769227825e9fdf811e84601651a061521bf4`.
- sqlc regenerated only under `internal/storage/dbgen`; freshness passed.
- Control Plane vet/unit tests and the PostgreSQL 18 migration, transaction,
  restart, health, and shutdown integration fixture passed.
- Full `task validate` passed, including repository policy, formatting,
  contracts, both Go modules, web checks, container smoke, PostgreSQL, Edge
  lifecycle/WAL, and isolated race evidence.
- Two clean static, stripped, trimpath builds were byte-identical at SHA-256
  `aac4a9f47c4f6694cead314d2f879b1fc23ea4a4fff331f3517e7a4556e1af36`.

Security impact: no trust, credential, privilege, network, endpoint, schema, or
transaction behavior changed. The relocated boundary test rejects direct
storage/SQL/pgx imports from canonical API and domain packages.

Known limitation: this package adds no product capability. P1-W10 remains
blocked until P1-G1 is merged and its behavior-preserving evidence is accepted.
