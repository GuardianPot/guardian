# P1-W11 — Build the initial Web Console shell

## 1. Purpose

Deliver the authenticated Phase 1 operator path from login through environment,
Edge enrollment, and truthful device health.

## 2. Why now

The first connected-platform slice needs browser-level evidence that the
approved backend capabilities compose into an operator-usable workflow.

## 3. Inputs and decisions

- Static React/TypeScript/Vite SPA served by the Control Plane or reverse proxy.
- TanStack Query-class server state and React Router-class explicit routes.
- Radix Primitives with CSS Modules/variables; no global Redux-like store.
- Vitest + React Testing Library for components and Playwright for browser E2E.
- Cookie session and CSRF behavior from P1-W2; no token in localStorage.

## 4. Dependencies

P1-W1 through P1-W4 provide stable API contracts. P1-W5 and P1-W9 are
integration dependencies for final E2E and acceptance.

## 4.1 Product Owner implementation contract — 2026-08-29

The Product Owner approved `W11-C1-A` through `W11-C8-A` as one binding
implementation package:

- **W11-C1-A — staged, real-backend execution:** build the SPA foundation,
  authentication, environment/zone, enrollment-token, error/loading/denied,
  session-expiry, device, and health paths against approved APIs. Test doubles
  remain test-only and can never produce production green health.
- **W11-C2-A — frontend architecture:** use React, TypeScript, Vite, an explicit
  React Router route tree, TanStack Query for server state, Radix Primitives
  with CSS Modules and variables, and React primitives for local state. Do not
  add a Redux-like global store, SSR, unsafe HTML, or an inline-script
  requirement. Resolve and pin the newest secure supported releases.
- **W11-C3-A — session and secret lifetime:** send only the HttpOnly Secure
  SameSite session cookie with `credentials: include`; keep CSRF in memory. A
  hard reload may restore read-only session state but requires reauthentication
  before mutation or logout. Session, CSRF, TOTP, recovery, bootstrap,
  enrollment, and private-key material must not enter browser storage, URLs,
  query caches, logs, analytics, screenshots, traces, or videos. One-time
  enrollment secrets leave DOM and memory on dismissal, route exit, or unload.
- **W11-C4-A — canonical device inventory prerequisite:** add authorized,
  `no-store`, bounded `GET /v1/environments/{environmentId}/devices` and
  `GET /v1/environments/{environmentId}/devices/{deviceId}` reads. Return only
  device ID, environment ID, display name, state, timestamps, and optional
  active-certificate expiry. Authorization precedes storage access, ordering is
  deterministic, and lists are capped at 200.
- **W11-C5-A — same-origin static SPA delivery:** build the SPA in a Node 24
  builder stage and serve immutable assets plus client-route fallback from the
  existing Control Plane HTTPS origin, without a Node runtime in the final
  image. Unknown `/v1` requests never fall back to the SPA. CSP permits only
  required self-hosted resources and excludes `unsafe-inline` and
  `unsafe-eval`; API and secret responses remain `no-store`.
- **W11-C6-A — truthful device and health UI:** display inventory state apart
  from health. Consume only P1-W9 projections, render all eight conditions as
  text, identify blocking/source devices, distinguish `False` from `Unknown`,
  and never infer healthy from process or channel presence.
- **W11-C7-A — browser and security evidence:** use Vitest and React Testing
  Library for routes, forms, errors, secret lifetime, and hostile text. Run
  Playwright Chromium, Firefox, and WebKit against the real onboarding path,
  including accessibility, reduced motion, bundle budget, and storage/artifact
  secret scans. Secret-bearing steps disable traces, video, and screenshots;
  capture evidence only after explicit secret dismissal or redaction.
- **W11-C8-A — narrow integration path expansion:** the additional Control
  Plane API/app/config/devices/storage, Dockerfile, OpenAPI, deployment, and
  security-review paths in `allowed_paths` may change only for the read-only
  inventory API and same-origin static delivery. No new mutator, role model,
  session mechanism, external web runtime, release authority, Edge change, or
  device-plane protocol change is authorized.

## 4.2 Product Owner CI-remediation contract — 2026-08-29

The Product Owner approved `W11-C9-A` after the real-browser CI evidence exposed
an authentication concurrency defect and an invalid health-report fixture:

- **W11-C9-A — lock-ordered session authorization and truthful reconnect
  evidence:** session authorization must read PostgreSQL `clock_timestamp()`
  only after locking the session row, so concurrent authenticated requests
  cannot revoke a valid session because an earlier application timestamp is
  evaluated after a later request. Preserve the approved 15-minute idle and
  8-hour absolute expiry, CSRF, revocation, and clock-rollback fail-closed
  behavior. Add concurrent PostgreSQL regression evidence. The E2E health
  publisher must preserve `last_transition_time` when status and reason are
  unchanged across reconnect reports; backend transition-history validation
  remains unchanged.

## 5. Scope

- Login, TOTP, recovery-code, and logout screens.
- Environment list/detail/edit and zone definition.
- Edge enrollment-token wizard with one-time secret handling.
- Device list/detail and health condition views.
- Loading, empty, denied, expired-session, degraded, and error states.
- Browser flow: login → create environment → token → Edge enroll → healthy.

## 6. Non-goals

- Public marketing pages, SSR, design-system breadth, decoy management,
  incidents/journeys, AI, notifications, OIDC, role editor, or mobile-native app.

## 7. Allowed paths

Only Web Console source/tests/runbook, root npm lock metadata, the minimal
CI/task updates listed in frontmatter, and the owner-approved W11-C9-A auth
correction. Other API changes belong to upstream packages.

## 8. Security constraints

- Never store session, bootstrap, enrollment, recovery, or TOTP secrets in
  localStorage, logs, analytics, URL history, screenshots, or test artifacts.
- Escape all backend/hostile text; no raw HTML rendering.
- Enforce CSP-compatible code and avoid unsafe inline script requirements.
- Health is backend truth; disconnected mocks cannot render green.

## 9. Implementation requirements

- Pin newest secure supported dependency versions and commit the lockfile.
- Accessibility includes keyboard navigation, labels, focus handling, error
  association, and reduced-motion-safe behavior.
- Typed API client derives from the approved OpenAPI contract or a thin typed
  wrapper; do not duplicate DTO semantics.
- A sequential PR chain is allowed for foundation/components/final E2E, with
  all PRs linked to P1-W11 and acceptance only after real integration.

## 10. Required tests

- Vitest/React Testing Library for auth, forms, errors, secret lifetime, health,
  and hostile rendering.
- Playwright Chromium/Firefox/WebKit for the onboarding path.
- Session expiry, CSRF failure, invalid token, degraded health, and reconnect.
- Concurrent authenticated request fan-out does not revoke a valid session.
- Accessibility smoke and production build/bundle check.

## 11. Acceptance criteria

- Operator can complete the real login/environment/enrollment/health flow.
- TOTP and one-time secrets are handled without browser persistence leakage.
- Device health shows actionable real backend state.
- Hostile content does not execute and browser E2E passes.

## 12. Evidence required

Screenshots with secrets redacted, browser traces/videos with secret masking,
accessibility results, dependency/license review, bundle output, and CI links.

## 13. Stop and escalate

Stop for API semantic changes, tokens in localStorage, unsafe HTML, a new global
state architecture, SSR/server runtime, design/product scope beyond the listed
screens, or tests that rely on fake green backend state.

## 14. Deliverables

Web Console shell, accessible components/routes, typed API integration, unit and
browser tests, screenshots, and operator runbook.
