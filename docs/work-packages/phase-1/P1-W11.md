# P1-W11 — Build the initial Web Console shell

## 1. Purpose

Deliver the authenticated Phase 1 operator path from login through environment,
Edge enrollment, and truthful device health.

## 2. Why now

The first connected-platform slice needs browser-level evidence that the
approved backend capabilities compose into an operator-usable workflow.

## 3. Inputs and decisions

- Static React/TypeScript/Vite SPA served by the Control Plane or reverse proxy.
- TanStack Query-class server state and React Router-class explicit routes.
- Radix Primitives with CSS Modules/variables; no global Redux-like store.
- Vitest + React Testing Library for components and Playwright for browser E2E.
- Cookie session and CSRF behavior from P1-W2; no token in localStorage.

## 4. Dependencies

P1-W1 through P1-W4 provide stable API contracts. P1-W5 and P1-W9 are
integration dependencies for final E2E and acceptance.

## 5. Scope

- Login, TOTP, recovery-code, and logout screens.
- Environment list/detail/edit and zone definition.
- Edge enrollment-token wizard with one-time secret handling.
- Device list/detail and health condition views.
- Loading, empty, denied, expired-session, degraded, and error states.
- Browser flow: login → create environment → token → Edge enroll → healthy.

## 6. Non-goals

- Public marketing pages, SSR, design-system breadth, decoy management,
  incidents/journeys, AI, notifications, OIDC, role editor, or mobile-native app.

## 7. Allowed paths

Only Web Console source/tests/runbook, root npm lock metadata, and the minimal
CI/task updates listed in frontmatter. API changes belong to upstream packages.

## 8. Security constraints

- Never store session, bootstrap, enrollment, recovery, or TOTP secrets in
  localStorage, logs, analytics, URL history, screenshots, or test artifacts.
- Escape all backend/hostile text; no raw HTML rendering.
- Enforce CSP-compatible code and avoid unsafe inline script requirements.
- Health is backend truth; disconnected mocks cannot render green.

## 9. Implementation requirements

- Pin newest secure supported dependency versions and commit the lockfile.
- Accessibility includes keyboard navigation, labels, focus handling, error
  association, and reduced-motion-safe behavior.
- Typed API client derives from the approved OpenAPI contract or a thin typed
  wrapper; do not duplicate DTO semantics.
- A sequential PR chain is allowed for foundation/components/final E2E, with
  all PRs linked to P1-W11 and acceptance only after real integration.

## 10. Required tests

- Vitest/React Testing Library for auth, forms, errors, secret lifetime, health,
  and hostile rendering.
- Playwright Chromium/Firefox/WebKit for the onboarding path.
- Session expiry, CSRF failure, invalid token, degraded health, and reconnect.
- Accessibility smoke and production build/bundle check.

## 11. Acceptance criteria

- Operator can complete the real login/environment/enrollment/health flow.
- TOTP and one-time secrets are handled without browser persistence leakage.
- Device health shows actionable real backend state.
- Hostile content does not execute and browser E2E passes.

## 12. Evidence required

Screenshots with secrets redacted, browser traces/videos with secret masking,
accessibility results, dependency/license review, bundle output, and CI links.

## 13. Stop and escalate

Stop for API semantic changes, tokens in localStorage, unsafe HTML, a new global
state architecture, SSR/server runtime, design/product scope beyond the listed
screens, or tests that rely on fake green backend state.

## 14. Deliverables

Web Console shell, accessible components/routes, typed API integration, unit and
browser tests, screenshots, and operator runbook.
