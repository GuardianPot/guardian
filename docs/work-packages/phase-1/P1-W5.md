# P1-W5 — Implement the gRPC device channel

## 1. Purpose

Create the authenticated, reconnecting, bounded bidirectional channel that
carries device heartbeat, desired state, and observed status.

## 2. Why now

Enrollment establishes identity, but Phase 1 needs a durable management loop
that survives Control Plane and network interruption.

## 3. Inputs and decisions

- Edge dials outbound gRPC over HTTP/2 with per-device mTLS.
- Deployment profile exposes a dedicated device endpoint on TCP/443; local
  development may map a non-privileged port while preserving that profile.
- Heartbeat every 30 seconds; connection is stale after 90 seconds.
- Full-jitter exponential reconnect from 1 to 60 seconds.
- Control-plane message limit is 1 MiB; large payloads use a separate future
  blob path.

### Product Owner contract — 2026-08-28

The Product Owner approved W5-C1-A through W5-C7-A as one package.

- **W5-C1-A — staged ownership:** P1-W5 owns the real authenticated transport,
  negotiated stream, heartbeat, revision/ack framing, truthful local channel
  health, and handler seams. P1-W6 retains durable desired/observed semantics
  and restart idempotency; P1-W9 retains durable health projection and
  aggregate; P1-W11 retains UI. No production mock may claim those later gates.
- **W5-C2-A — v1 contract:** one `DeviceChannel.Connect` bidirectional RPC uses
  an Edge hello followed by Control Plane protocol selection. The initial
  protocol is major 1/minor 0. Incompatible major or newer client minor yields
  an explicit protocol-incompatible response followed by `FailedPrecondition`.
  Retriable state frames carry UUIDv7 message IDs and revision/ack fields.
  P1-W5 transports revision-only desired/observed envelopes; P1-W6 adds the
  approved typed objects atomically. Opaque configuration blobs and development
  compatibility shims are forbidden.
- **W5-C3-A — identity binding:** TLS 1.3 is the minimum. Product-device CA
  verification and durable P1-W4 active-serial/device-state verification happen
  before application frames. Identity comes only from the certificate URI SAN.
  Eligibility is rechecked every 30 seconds and before state-bearing frames.
  Edge verifies the server name against its operating-system trust store.
- **W5-C4-A — lifecycle:** heartbeat is 30 seconds and stale is 90 seconds.
  Hello has a 10-second deadline. Reconnect uses full-jitter exponential delay
  from 1 to 60 seconds and resets only after a negotiated stream remains stable
  for 90 seconds. One active stream is allowed per device; a newer fully
  authenticated stream atomically replaces and cancels the older stream.
- **W5-C5-A — bounds:** both peers enforce a 1 MiB gRPC message limit and
  16 KiB metadata/header budget. Each direction is bounded by 64 frames and
  4 MiB. Enqueue is non-blocking and returns typed backpressure. Coalescible
  heartbeat/revision snapshots may replace older unsent values; state-bearing
  frames are not silently discarded. Health reports remain at most 16 KiB with
  a per-device rate of 6/minute and burst 3.
- **W5-C6-A — observability and evidence:** only W3C trace context propagates.
  Credentials, full certificates, payloads, and arbitrary metadata are excluded
  from logs and telemetry. Shutdown drains within the configured deadline and
  then force-stops. The deployment profile maps a dedicated non-privileged
  listener to a 443-compatible endpoint. Every required security, restart,
  failure, saturation, cancellation, and rate-limit case is blocking evidence.
- **W5-C7-A — path revision:** the added dependency, generation, composition,
  configuration, and Taskfile paths in `allowed_paths` are limited to P1-W5.
  Generated channel code remains under the device-channel roots. Dependencies
  use the newest secure supported versions available at implementation time.

## 4. Dependencies

P1-W4 device identity/enrollment and P1-W7 Edge daemon lifecycle.

## 5. Scope

- TLS/mTLS listener and outbound Edge dialer.
- Certificate-to-device authorization.
- Heartbeat, connection status, reconnect/backoff, and graceful shutdown.
- Explicit protocol version negotiation.
- Desired-state and observed-state/status streams with bounded queues.
- OpenTelemetry context and safe diagnostics.

## 6. Non-goals

- Telemetry/file bulk transfer, external broker, inbound Control Plane dialing,
  WebSocket fallback, or production load-balancer vendor selection.

## 7. Allowed paths

Only the device-channel implementations, versioned device contract, deployment
profile, tests, security evidence, and protocol/runbook paths in frontmatter.

## 8. Security constraints

- TLS 1.3 preferred and obsolete TLS disabled.
- Every stream is bound to a valid non-revoked device identity.
- Invalid, expired, revoked, malformed, oversized, or unauthorized input fails
  closed without process crash or secret leakage.
- No private keys or full certificate credentials in diagnostics.

## 9. Implementation requirements

- Bounded send/receive queues and explicit stream cancellation.
- Backoff uses full jitter and resets only after a stable connection.
- Version mismatch produces an explicit health condition.
- During development, breaking protocol updates require owner review and an
  atomic update of all repository consumers; no legacy compatibility path.
- Control restart reconnects without creating duplicate device state.

## 10. Required tests

- Valid connection, invalid/revoked/expired certificate, and identity mismatch.
- Control restart, Edge restart, network interruption, reconnect, and backoff.
- Heartbeat stale/recovery transitions.
- Malformed and oversized Protobuf, queue saturation, and cancellation.
- Protocol mismatch and duplicate connection policy.

## 11. Acceptance criteria

- Restart/reconnect succeeds with truthful connection state.
- Invalid or revoked certificates are rejected.
- Incompatible protocol produces an actionable health condition.
- Limits and backpressure prevent unbounded memory growth and process crash.

## 12. Evidence required

Packet/listener profile without secrets, integration/failure-injection results,
resource-bound evidence, security review, and CI links.

## 13. Stop and escalate

Stop for a broker, alternate transport, TLS weakening, arbitrary public
endpoint behavior, unbounded messages, or semantic contract change outside the
approved desired/observed-state scope.

## 14. Deliverables

Control/Edge channel implementations, versioned contract updates, deployment
profile, protocol documentation, security tests, and reconnect runbook.
