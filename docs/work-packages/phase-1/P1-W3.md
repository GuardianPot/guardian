# P1-W3 — Implement the environment domain

## 1. Purpose

Create the single-organization environment and private IPv4 zone model used by
enrollment, desired state, health, and later deception placement.

## 2. Why now

Devices and desired state require stable environment ownership and validated
network-zone identities before they can be connected safely.

## 3. Inputs and decisions

- One organization singleton with multiple environments.
- Environment create/read/update; deletion is not part of Phase 1.
- RFC1918/private IPv4 zones using canonical CIDR representation.
- Any overlap inside the same environment is rejected in Phase 1.
- Saving configuration never performs an active network scan.

## 4. Dependencies

P1-W1 module/database foundation and P1-W10 audit append API.

## 5. Scope

- Organization singleton initialization.
- Environment create/read/update and status projection.
- Zone/CIDR create/read/update/remove within an environment.
- Canonical CIDR, duplicate, overlap, and input validation.
- Before/after audit references for all mutations.

## 6. Non-goals

- Multi-tenancy, arbitrary public networks, IPv6, VLAN automation, active
  discovery, IP allocation, decoy placement, or environment deletion.

## 7. Allowed paths

Only the environment domain, its API/storage adapters, tests, and runbook paths
listed in frontmatter.

## 8. Security constraints

Reject malformed, public, loopback, link-local, multicast, zero-prefix, and
overlapping CIDRs. Authorization must scope every mutation to the authenticated
organization context.

## 9. Implementation requirements

- Use Go `net/netip`-class canonical parsing and containment checks.
- Enforce overlap and uniqueness in both domain validation and transactional
  persistence where possible.
- Store normalized prefix/network values, not user formatting.
- Return actionable validation errors without leaking database details.

## 10. Required tests

- At least two valid RFC1918 zones in one environment.
- Duplicate, nested, partial-overlap, public, malformed, and boundary CIDRs.
- Concurrent update conflict and transaction rollback.
- Save-without-scan assertion and complete audit history.

## 11. Acceptance criteria

- AC-ON-003 passes with at least two private IPv4 zones.
- Dangerous/ambiguous overlapping configuration is rejected deterministically.
- Save causes no probe, scan, route, address, or firewall mutation.
- Owner-visible status and audit history survive restart.

## 12. Evidence required

API examples, validation matrix, PostgreSQL integration results, audit samples,
and CI links.

## 13. Stop and escalate

Stop for IPv6 or public-network scope, nested-zone precedence, active discovery,
automatic network changes, or a schema that introduces multi-tenancy behavior.

## 14. Deliverables

Environment module, OpenAPI contract, migrations/queries, validation tests, and
operator documentation.
