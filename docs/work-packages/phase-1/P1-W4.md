# P1-W4 — Implement Edge enrollment and revocation

## 1. Purpose

Turn the Phase 0 disposable PKI proof into the product-owned, persistent Edge
enrollment, certificate rotation, and revocation lifecycle.

## 2. Why now

The device channel cannot establish production-shaped identity or authorization
until Edge records and one-time enrollment are durable and auditable.

## 3. Inputs and decisions

- Product-specific X.509 device CA using standard Go cryptography.
- Edge generates and retains its own private key.
- One-time enrollment tokens expire after 15 minutes and are hashed at rest.
- Device certificates are valid for 30 days and rotate with jitter during the
  final 10 days.
- Central CA material uses the SecretStore boundary; no plaintext CA key in
  PostgreSQL or logs.

### Product Owner contract W4-C1-A through W4-C7-A

- P1-W4 package acceptance covers the real durable enrollment and certificate
  lifecycle plus product mTLS-verifier evidence. Live channel, health, and
  browser evidence remain mandatory P1-W5/P1-W9/P1-W11 integration gates.
- Control Plane creates a UUIDv7 device identity. A 32-byte Base64URL token is
  bound to exactly one environment and device, expires after 15 minutes, is
  persisted only as a SHA-256 hash, and is consumed or revoked atomically.
- Edge generates an ECDSA P-256 key in an owner-only non-symlink file. Device
  certificates use a random 128-bit serial, a device UUID URI SAN, a 30-day
  lifetime, and jittered rotation during the final 10 days. Activating a
  rotated certificate atomically revokes the previous serial.
- The local SecretStore backend uses AES-256-GCM and a required mounted 32-byte
  owner-only master-key file outside the repository and database. Missing or
  invalid key material fails closed; serve never silently generates a CA.
- Operator endpoints use the approved browser-session, CSRF, origin, and
  organization-scope boundaries and default-deny until P1-W2 integration. The
  enrollment exchange requires TLS plus the one-time bearer token and bounded,
  generic, no-store request/response behavior with persistent throttling.
- Disable blocks new sessions and token issuance until an explicit re-enable.
  Revoked serials never reactivate; re-enrollment requires a new one-time token
  for the stable device record.
- The additional allowed paths above are restricted to P1-W4 behavior. P1-W2
  retains browser-session ownership, P1-W3 environment semantics, P1-W5 the
  management channel, and P1-W9 health projection.

## 4. Dependencies

P1-W1 persistence, P1-W7 Edge identity/storage shell, P1-W10 audit, and the
accepted P0-W9 PKI evidence inherited through the Phase 0 gate.

## 5. Scope

- Authenticated enrollment-token create/list/revoke API.
- Edge key generation, CSR construction, and enrollment exchange.
- Certificate issuance, persistence metadata, rotation, and expiry state.
- Device record, connection eligibility, disable/revoke, and re-enrollment
  boundary.
- Audit for token, issuance, rotation, disable, and revocation actions.

## 6. Non-goals

- TPM requirement, enterprise PKI, SPIFFE/SPIRE, production KMS vendor,
  multi-device fleet rollout, or Web Console wizard.

## 7. Allowed paths

Only the PKI/device, Edge enrollment, contract, test, security, and runbook
paths listed in frontmatter.

## 8. Security constraints

- Token and certificate use is bound to the intended environment/device flow.
- Token consume is atomic and replay-safe.
- Edge private keys never cross the device API or enter logs.
- Revoked/disabled identities cannot establish a new management session.
- Test fixtures use disposable CA material only.

## 9. Implementation requirements

- Use cryptographically random token material with only a hash persisted.
- Issue certificates only after CSR validation and explicit token consume.
- Persist serial, validity, fingerprint, state, and rotation metadata.
- Provide a protected local SecretStore development backend using a mounted
  master-key file; keep hosted KMS behind the stable interface and out of scope.
- Update all development protocol consumers atomically; add no compatibility
  layer for obsolete development contracts.

## 10. Required tests

- Fresh enrollment, expired/invalid/revoked/used token, and concurrent replay.
- CSR/key mismatch, malformed CSR, and unsupported key/signature input.
- Rotation before/inside the window and service restart during rotation.
- Device disable/revoke and rejected new mTLS session.
- Secret/log scan and filesystem permission assertions.

## 11. Acceptance criteria

AC-ON-001, AC-ON-002, AC-SEC-005, and AC-SEC-006 pass with durable audit
evidence and no Edge private-key disclosure.

## 12. Evidence required

Enrollment/rotation/revocation test logs, redacted certificate metadata, threat
review, SecretStore boundary evidence, and CI links.

## 13. Stop and escalate

Stop for custom cryptography, plaintext CA/device private keys, reusable tokens,
external PKI/KMS dependency, weaker revocation, or expanded device identity
semantics.

## 14. Deliverables

Enrollment and device modules, Edge identity client, API/contracts,
migrations/tests, security review, and operator runbook.

## 15. Implementation evidence — 2026-08-25

The implementation candidate on `agent/P1-W4-edge-enrollment` provides the
approved W4-C1-A through W4-C7-A contract within this package's allowed paths.

- PostgreSQL 18 stores only hashed enrollment tokens and authenticated CA-key
  ciphertext. Integration proves expiry, explicit revocation, exactly one
  winner under concurrent replay, stable-record re-enrollment, rotation-window
  enforcement, permanent serial revocation, persistent throttling after a new
  repository instance, and durable audit actions.
- The Control Plane provides explicit CA initialization, optional-but-atomic
  enrollment configuration, a TLS 1.3 listener, default-deny operator APIs,
  the TLS-only token bootstrap, and a product certificate verifier combining
  X.509 validation with current PostgreSQL eligibility.
- Edge generates and retains its P-256 key, validates the returned identity,
  installs matching certificate/key pairs through a restart-recoverable
  journal, presents the active product certificate for mTLS rotation, and uses
  deterministic jitter plus bounded retry during the final ten days.
- Control Plane and Edge unit suites pass under the pinned Go 1.27 Linux image
  with race detection. Linux `go vet`, the complete PostgreSQL storage
  integration suite, Protobuf lint, OpenAPI validation, canonical contracts,
  secret scanning, dependency policy, workflow pinning, and formatting pass.
- The development runbook and security review document initialization,
  operator actions, recovery, trust boundaries, evidence, and residual risks.

The repository-wide Ubuntu `task validate` result and immutable GitHub Actions
link remain required before security/acceptance review. Windows-native policy
parsing still reports the baseline CRLF-sensitive P1-G0 frontmatter error, and
Windows cannot compile the Linux-only privileged peer-credential files; pinned
Linux tests are authoritative and no gate is waived.

Known limitations remain explicit: P1-W2 must provide the browser-session
authorizer, P1-W3 owns environment semantics, P1-W5 must use the verifier for
the live management channel, P1-W9 owns health projection, and P1-W11 owns
browser evidence. The local SecretStore is development-only and does not claim
hosted KMS/HSM, production disaster recovery, or live connectivity readiness.
