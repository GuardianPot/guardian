# P1-W7 — Build the Edge daemon production skeleton

## 1. Purpose

Convert the Edge placeholder and Phase 0 SQLite proof into a restart-safe,
unprivileged host daemon foundation with explicit local diagnostics.

## 2. Why now

Enrollment, the device channel, reconciliation, privileged operations, and
health all need a stable Edge lifecycle and durable local state boundary.

## 3. Inputs and decisions

- Go native `systemd` service; main agent runs unprivileged.
- SQLite WAL via the approved development driver.
- Filesystem spool interfaces with SQLite metadata; no large blobs in SQLite.
- Minimal local diagnostics CLI, not a second management UI.
- No silent fallback from failed secure enrollment.

## 4. Dependencies

P1-G0, Product Owner Phase 0 gate approval, and accepted Phase 0 SQLite/PKI/
contract evidence.

## 5. Scope

- Process lifecycle, configuration, signal handling, and structured logging.
- Local SQLite schema/lifecycle for identity metadata, desired/observed state,
  retries, health, and spool metadata.
- Interfaces for enrollment, channel, reconciler, health, telemetry spool, and
  privileged-helper client.
- Read-only diagnostics command for status and safe support output.

## 6. Non-goals

- Root monolith, real decoy lifecycle, network mutation, update system,
  production packaging matrix, local web UI, or large hostile-file ingestion.

## 7. Allowed paths

Only the Edge daemon, its deployment/test/runbook paths, and narrowly scoped
Edge fixture/task updates listed in frontmatter.

## 8. Security constraints

Run unprivileged, create files with restrictive permissions, redact credentials,
and never expose the device private key through diagnostics. Failure to load a
valid identity is explicit and cannot trigger insecure enrollment.

## 9. Implementation requirements

- Components have explicit start/stop order and context cancellation.
- Restart recovers durable state without duplicate work.
- Database corruption enters a named failed condition; recovery requires an
  explicit operator command that quarantines the corrupt development DB and
  initializes a new one. No data-preservation layer is required.
- Diagnostics output is bounded and supports machine-readable output.

## 10. Required tests

- Startup/shutdown, missing config, signal, and component failure.
- SQLite restart, lock contention, disk-full simulation, and corruption state.
- File permission and diagnostics secret-redaction tests.
- Explicit recovery command and no-silent-reset assertion.

## 11. Acceptance criteria

- Restart restores local state and pending retry metadata.
- Corruption produces a precise failure state and reproducible recovery path.
- Enrollment failure never falls back to plaintext/insecure identity.
- Main daemon has no root requirement for normal control-loop work.

## 12. Evidence required

Service/permission profile, restart/corruption logs, redacted diagnostics sample,
dependency review, and CI links.

## 13. Stop and escalate

Stop for broad root authority, Docker/containerd socket exposure to the main
agent or decoys, silent database reset, production secret, or a new local DB.

## 14. Deliverables

Edge daemon skeleton, SQLite lifecycle, component interfaces, diagnostics CLI,
failure fixtures, service profile, and runbook.

## 15. Implementation evidence — 2026-08-23

Decision references: EN-01, EN-02, EN-03, EN-05, EN-06, EN-08, EN-12,
SA-05, and OB-01. Acceptance reference: Phase 1 P1-W7 acceptance.

Implemented paths:

- `apps/edge-agent/**`: explicit CLI/config, protected identity loading,
  ordered lifecycle, component interfaces, SQLite/CAS state, bounded read-only
  diagnostics, corruption classification, and explicit development recovery;
- `deploy/edge-agent/**`: dedicated no-login user, protected directories,
  hardened systemd unit, non-secret configuration, and dependency inventory;
- `tests/integration/edge-agent/run.sh`: real-process startup, SIGTERM, restart,
  WAL replay, corruption, recovery, permission, and redaction evidence;
- `docs/runbooks/edge-agent/**`: operations and recovery runbook plus redacted
  diagnostic sample;
- `Taskfile.yml`: pinned module verification, unprivileged integration and WAL
  fixtures, plus network-isolated race tests in the digest-pinned Go builder.

Initial evidence:

- `GOWORK=off go -C apps/edge-agent test ./...`: PASS;
- `GOWORK=off go -C apps/edge-agent vet ./...`: PASS;
- `bash tests/integration/edge-agent/run.sh`: PASS;
- the Phase 0 `bash tools/edge-wal-fixture.sh` crash/replay contract: PASS;
- the post-P1-W1-rebase `task validate` full repository gate, including the
  shared `task go:check` Edge dependency, integration, WAL, and race path: PASS;
- CGO-enabled `go test -race ./...` in the digest-pinned Go 1.27 Debian builder
  with source/module cache read-only and network disabled: PASS;
- `govulncheck` v1.7.0: no vulnerabilities; `go-licenses` v2.0.1 external
  runtime dependency check: PASS; selected-module retraction and `go mod verify`:
  PASS;
- `systemd-analyze verify`: PASS in a disposable rooted install; offline
  `systemd-analyze security`: `1.5 OK`;
- two clean static, stripped, trimpath builds were byte-identical at SHA-256
  `3bc77cc049ead4e9fa8bd07c58d78083a210d1492e77e1801e4c800795603eb4`;
- missing configuration and missing identity fail explicitly before state
  creation;
- restart preserves identity, desired/observed/last-good revisions, retry
  metadata, health, queue, and CAS metadata;
- corruption remains byte-identical until the confirmation-gated recovery
  command quarantines it and initializes the current development schema;
- DB/key/object modes are `0600`, state/spool directories are `0700`, and
  diagnostics/log tests contain no key path or private-key body.

Security impact:

- the main daemon runs without root or Linux capabilities and has no shell,
  runtime-socket, network-mutation, or privileged-helper implementation;
- startup requires a valid matching protected identity and has no insecure
  enrollment/transport fallback;
- SQLite contains bounded metadata while event content uses a hash-verified
  protected filesystem CAS;
- diagnostic rows/output are bounded and accept only redaction-safe condition
  and error codes.

Known limitations:

- enrollment, device-channel traffic, reconciliation, privileged operations,
  full health, spool eviction, and packaging remain later-package work;
- OpenTelemetry exporter configuration is deferred to the observability package;
- the exact current development schema is required; older development DBs use
  the explicit reset/reseed path and receive no compatibility layer.
