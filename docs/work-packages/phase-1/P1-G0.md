# P1-G0 — Establish Phase 1 execution baseline

## 1. Purpose

Create the reviewable repository and GitHub execution baseline for Phase 1
without starting Phase 1 product implementation.

## 2. Why now

Phase 0 technical evidence exists, while Phase 1 package specifications,
context routing, gate evidence, and complete Project semantics do not.

## 3. Inputs and decisions

- Product Owner approval of D1-A through D11-A on 2026-08-22.
- Step 6 Phase 1 roadmap and agent execution governance.
- Step 7 context, work-package, and Project decisions.

## 4. Dependencies

No product dependency. Phase 0 gate approval is deliberately not part of this
planning-only package.

## 5. Scope

- Phase-agnostic agent and issue guidance.
- Context map, Phase 1 package catalog, dependency graph, and gate.
- Repository policy validation for the new artifacts.
- GitHub Project status, field, and component alignment.

## 6. Non-goals

- Phase 1 product code or dependency installation.
- Phase 0 gate approval.
- Activating P1-W1 through P1-W11 before owner content approval.
- GitHub plan upgrade.

## 7. Allowed paths

Only the paths listed in frontmatter plus the organization Project configuration
approved by D4-A.

## 8. Security constraints

Do not add secrets, production keys, deployment credentials, or weaken any
existing review boundary.

## 9. Implementation requirements

Use one atomic PR. P1-W1 through P1-W11 must use YAML frontmatter and all
mandatory work-package sections. Owner content approval moves them to
`approved-for-implementation`; dependency closure controls Project readiness.

## 10. Required tests

- `npm run format:check`
- `npm run policy:check`
- `task validate`
- `git diff --check`

## 11. Acceptance criteria

- All Phase 1 specifications are reviewable in one PR.
- Context routing and gate authority are explicit.
- Project fields match approved execution semantics.
- Phase 0 remains unapproved.

## 12. Evidence required

- Issue and PR links.
- Project field snapshot.
- Complete local validation and green PR CI.

## 13. Stop and escalate

Stop if the package requires product code, changes an approved architecture or
acceptance criterion, or attempts to bypass the Phase 0 human gate.

## 14. Deliverables

- Phase 1 execution documentation and policy checks.
- Aligned `Guardian Delivery` Project configuration.
- One owner-reviewable planning PR.
