# P1-W9 — Implement the platform health model

## 1. Purpose

Expose truthful, actionable health conditions from Edge runtime facts through
the Control Plane to the Web Console.

## 2. Why now

Phase 1 is not acceptable if connectivity or process-up signals can create a
false green state while identity, reconciliation, storage, or privilege is
broken.

## 3. Inputs and decisions

- Conditions use `True`, `False`, or `Unknown` status plus stable type, reason,
  bounded message, observed revision, and transition time.
- Initial types: Edge connected, cert valid, config converged, local DB healthy,
  spool healthy, clock quality, container runtime reachable, and privileged
  helper reachable.
- Heartbeat is 30 seconds and connectivity becomes stale after 90 seconds.
- UI never substitutes mock health for backend truth.

## 4. Dependencies

P1-W1, P1-W7, and P1-W8 allow the health domain to begin. P1-W4, P1-W5, and
P1-W6 are integration dependencies that must close before acceptance.

## 4.1 Product Owner implementation contract — 2026-08-24

The Product Owner approved `W9-C1-A` through `W9-C7-A` as one binding
implementation package:

- **W9-C1-A — staged execution:** the first PR implements the canonical
  contract, domain transitions, and tests only. Real transport, persistence,
  route composition, and failure injection integrate after their P1-W4,
  P1-W5, P1-W6, and P1-W11 seams exist. Production code has no fake backend,
  mock-green path, or compatibility adapter.
- **W9-C2-A — canonical condition envelope:** use exactly
  `edge_connected`, `device_certificate_ready`, `config_converged`,
  `local_database_healthy`, `spool_healthy`, `clock_quality`,
  `container_runtime_reachable`, and `privileged_helper_reachable`. Status is
  exactly `True`, `False`, or `Unknown`; type and reason are closed identifiers
  bounded to 64 bytes; message is escaped, secret-free plain UTF-8 bounded to
  512 bytes; observed revision is an optional non-negative `uint64`; and
  timestamps are UTC at microsecond precision.
- **W9-C3-A — report protocol:** every 30 seconds, Edge emits one full snapshot
  containing exactly one instance of all eight conditions; absent knowledge is
  `Unknown`, never an omitted condition. The report is at most 16 KiB and
  carries a UUIDv7 report ID plus a durable per-device monotonic `uint64`
  sequence. Device identity comes from mTLS. Exact duplicates are idempotent,
  older or out-of-order reports cannot replace newer truth, and Phase 1 has no
  delta report.
- **W9-C4-A — transitions, staleness, and aggregate:**
  `last_transition_time` changes only when `(status, reason)` changes; message
  or revision refresh does not reset it. Control Plane receive time, not the
  Edge clock, drives staleness. Before evidence or after 90 seconds without a
  valid full report, connectivity is `Unknown/heartbeat_stale`; an explicitly
  closed channel is `False/channel_disconnected`. Aggregate is `False` if any
  blocking condition is False, otherwise `Unknown` if any is Unknown or stale,
  otherwise `True`; all eight conditions block a green aggregate. Recovery
  requires fresh evidence and clears only the affected condition.
- **W9-C5-A — Phase 1 thresholds:** certificate readiness is False in the
  approved final 10-day rotation window and for expired, revoked, or
  rotation-failed states. Clock quality is True only with confirmed
  synchronization and absolute offset no greater than five seconds. Spool
  health is False at 80 percent configured capacity or below 10 percent
  filesystem free, with a critical reason at 95 percent or below five percent.
  Failed database read, write, or integrity evidence is False. Helper and
  runtime typed probes use a two-second timeout; one failed fresh probe marks
  False and one fresh success recovers only that condition. Unavailable
  measurements are Unknown.
- **W9-C6-A — API and ingest security:** expose read-only
  `GET /v1/environments/{environmentId}/health` and
  `GET /v1/devices/{deviceId}/health`, with no health mutator API. Cookie
  authorization and environment scope precede reads and default-deny until
  P1-W2. Responses use `Cache-Control: no-store`, and hostile messages are
  never markup. P1-W5 enforces the 16 KiB report limit and a per-device token
  bucket of six reports per minute with burst three.
- **W9-C7-A — narrow package revision:** the additional Control Plane app and
  storage, Edge app/components/privclient/storage, and root Taskfile paths in
  `allowed_paths` may change only for P1-W9 health behavior and only after
  conflicting dependency work is rebased or closed. P1-W5 continues to own
  device-channel transport, P1-W6 owns reconciliation integration, and P1-W11
  owns Web Console route and shell composition.

## 4.2 Product Owner continuation contract — 2026-08-29

The Product Owner approved `W9-C8-A` through `W9-C13-A` as one binding
continuation package:

- **W9-C8-A — current-session disconnect truth:** device-channel closure marks
  only the session that is still current as disconnected. Replacement of an
  older channel cannot mark the replacement session disconnected. The next
  accepted full report from the current session clears the disconnect
  override.
- **W9-C9-A — durable canonical report and acknowledgement:** Control Plane
  PostgreSQL migration 7 and Edge SQLite schema 3 persist all eight canonical
  conditions, report sequence, exact pending payload, and acknowledgement
  state. Edge sends immediately on start and every 30 seconds, replays an
  unacknowledged payload byte-for-byte after restart, and clears it only for
  the matching acknowledgement. Existing development schema 2 databases use
  the approved reset-and-reseed recovery; no compatibility shim is added.
- **W9-C10-A — environment aggregation:** aggregate only active devices, with
  severity `False` before `Unknown` before `True`. A tie is attributed to the
  lowest device UUID. Device condition responses may include
  `source_device_id`; the aggregate may include `blocking_device_id`. An
  environment with zero active devices is `Unknown/no_active_devices`.
  Pending, disabled, and revoked devices remain inventory-visible but do not
  contribute to the operational aggregate.
- **W9-C11-A — bounded Edge evidence collection:** collect certificate,
  reconciliation, SQLite read/write/quick-check, spool capacity and free-space,
  `adjtimex` clock, helper, and runtime evidence. Configuration requires
  `spool_capacity_bytes` between 64 MiB and 1 TiB; the deployment example uses
  1 GiB.
- **W9-C12-A — fixed privileged runtime probe:** add a parameterless,
  read-only `GetRuntimeStatus` helper operation. The privileged helper alone
  probes the fixed `/run/containerd/containerd.sock` path with a two-second
  Version RPC using pinned `github.com/containerd/containerd/api` v1.11.1.
  Edge receives only a bounded state and stable reason: no arbitrary command,
  caller-selected path, lifecycle operation, or runtime metadata enters health
  messages.
- **W9-C13-A — health-only path expansion:** the additional device-channel,
  configuration, privileged helper/protocol, module, deployment, workflow, and
  security-review paths in `allowed_paths` may change only for P1-W9 health.
  This grants no decoy, attacker-facing networking, general privilege,
  credential, signing, release, or repository-administration authority.
- **W9-C14-A — atomic strict-config test consumer:** the existing CLI command
  test fixture in `apps/edge-agent/cmd/edge-agent/main_test.go` may add only the
  approved 1 GiB `SpoolCapacityBytes` value required by W9-C11-A. This grants no
  production CLI behavior, command, recovery, credential, release, or other
  `cmd/**` change authority.
- **W9-C15-A — CI lifecycle strict-config consumer:** the existing Edge
  lifecycle fixture in `tests/integration/edge-agent/run.sh` may add only the
  approved 1 GiB `spool_capacity_bytes` JSON value required by W9-C11-A. This
  grants no lifecycle logic, assertion, timing, cleanup, production, recovery,
  credential, release, or other `tests/integration/edge-agent/**` change
  authority.

## 5. Scope

- Edge condition collection, transition rules, persistence, and reporting.
- Control Plane ingestion, projection, aggregate environment status, and API.
- Environment and Edge health views with actionable degraded reasons.
- Failure transition and recovery evidence for helper/runtime/channel/storage.

## 6. Non-goals

- Customer SLA, alert notifications, full coverage verification, incident
  creation, Prometheus/Grafana product UI, or predictive health.

## 7. Allowed paths

Only the health slices, required contracts, tests, and runbook paths listed in
frontmatter. Cross-component changes must remain health-specific.

## 8. Security constraints

Health messages are bounded, enumerated where possible, and contain no private
keys, session secrets, raw database errors, arbitrary HTML, or attacker-supplied
content rendered as markup.

## 9. Implementation requirements

- Condition transitions are deterministic and preserve last transition time.
- Unknown differs from healthy and unhealthy.
- Aggregate status cannot be healthier than a blocking child condition.
- Stale data is explicit; timestamps and clock-quality condition are retained.
- Sequential PR chain is allowed for the contract/domain shell, but final
  acceptance waits for real P1-W4/W5/W6 integration.

## 10. Required tests

- Each condition's healthy, degraded, unknown, stale, and recovery transition.
- Stop/restart helper and container runtime intentionally.
- Disconnect/reconnect, expired/revoked cert, DB failure, and revision drift.
- API/UI hostile-message escaping and no-fake-green browser test.

## 11. Acceptance criteria

- Stopping helper/runtime produces the exact degraded condition.
- Connection, certificate, convergence, and storage truth survive restarts.
- UI shows the backend reason and never a disconnected mock green state.
- Recovery clears only the relevant condition after fresh evidence.

## 12. Evidence required

Condition matrix, transition fixtures, UI screenshots, browser results,
failure-injection logs, and CI links.

## 13. Stop and escalate

Stop for new alert/incident behavior, vendor observability dependency, health
based only on process-up, unbounded/raw error messages, or acceptance without
real integration evidence.

## 14. Deliverables

Health contracts/domain/reporting/UI, deterministic transition tests,
failure-injection evidence, screenshots, and operator runbook.
