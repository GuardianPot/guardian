# P1-W2 — Implement local user authentication

## 1. Purpose

Provide secure local owner/operator authentication for the Phase 1 console and
API without a default password or client-stored bearer credential.

## 2. Why now

Every operator-facing Phase 1 action requires an authenticated actor and audit
identity before UI and domain workflows can be trusted.

## 3. Inputs and decisions

- Single-organization local account baseline; OIDC and role editor are out.
- Argon2id password hashing and server-side PostgreSQL sessions.
- CLI-generated, 15-minute, one-time bootstrap token stored only as a hash.
- TOTP for owner/admin plus ten hashed single-use recovery codes.
- 15-minute idle and 8-hour absolute session expiry.
- Synchronizer CSRF token and secure same-origin browser policy.

## 4. Dependencies

P1-W1 persistence/API shell and P1-W10 append-oriented audit API.

## 5. Scope

- One-time admin bootstrap command and API exchange.
- Password creation, verification, change, and forced session invalidation.
- TOTP enrollment/verification and recovery-code consumption.
- Login, logout, session lookup/revocation, and auth audit events.
- Persistent account/source throttling with configurable thresholds.

## 6. Non-goals

- OIDC/SSO, password reset email, fine-grained RBAC, API tokens, passkeys, or
  multi-organization user administration.

## 7. Allowed paths

Only the authentication, API contract, test, security, and runbook paths listed
in frontmatter.

## 8. Security constraints

- Session tokens, bootstrap tokens, recovery codes, passwords, and TOTP codes
  never appear in logs or plaintext database columns.
- TOTP seeds use the approved SecretStore encryption boundary.
- Cookie name uses the `__Host-` prefix with Secure, HttpOnly, SameSite=Strict,
  path `/`, and no Domain attribute.
- State-changing requests require CSRF and origin validation.

## 9. Implementation requirements

- Calibrate Argon2id on the supported runtime while meeting or exceeding the
  current approved security minimum; store parameters with each hash.
- Rotate session identity after login and privilege-sensitive changes.
- Enforce idle and absolute expiry on the server.
- Default throttle: five failed attempts in five minutes, followed by
  exponential delay capped at fifteen minutes; make values configuration.
- Recovery codes are displayed once and each can be consumed once.

## 10. Required tests

- Bootstrap replay, expiry, and concurrent-use tests.
- Argon2 parameter, malformed hash, and timing-safe comparison tests.
- TOTP enrollment, drift-window, replay, and recovery-code tests.
- Session fixation, idle/absolute expiry, logout, revocation, and cookie tests.
- CSRF/origin, brute-force throttle, and secret-redaction integration tests.

## 11. Acceptance criteria

- No default password exists and bootstrap cannot be reused.
- The browser holds only an opaque session cookie, never the session secret's
  server-side record or a localStorage token.
- TOTP is required for owner/admin login.
- Failed logins and security changes create audit entries without secrets.

## 12. Evidence required

Auth threat-test results, redacted cookie/header evidence, audit samples,
dependency review, and CI links.

## 13. Stop and escalate

Stop for external identity services, JWT/localStorage UI auth, plaintext
secrets, weaker MFA, recovery behavior outside this package, or security tests
that require disabling controls.

## 14. Deliverables

Local auth module, bootstrap CLI, API contract, migrations/queries, security
tests, and operator recovery runbook.
