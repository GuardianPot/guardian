### Purpose and evidence

PR #49 quality run `33152480253` showed that the non-blocking Buf breaking
signal could not resolve a local `main` ref in a pull-request checkout. The
post-merge `main` run passed, proving that the failure was checkout-context
specific rather than a Protobuf compatibility result.

This correction makes the signal use the pull request's immutable base commit,
validates the selected Git object, retains safe local fallback behavior, and
adds blocking regression coverage. The existing development policy that makes
the breaking signal informational remains unchanged.

### Dependencies

P0-W1 and the repository quality workflow are present. No product or phase
dependency applies to this CI-only maintenance package.

### Non-goals and security constraints

- Do not change Protobuf contracts, product behavior, architecture, security
  boundaries, repository settings, secrets, or release authority.
- Do not interpolate an unvalidated ref into a shell command.
- Do not make owner-reviewed development breaking changes a blocking policy.
- Do not add dependencies or broaden the workflow's permissions.

### Implementation requirements

- Pull-request CI supplies the event's immutable base commit through
  `GUARDIAN_BUF_BASE_REF`.
- The script resolves the selected ref to a commit before both baseline
  inspection and Buf comparison.
- Local selection order is an explicit override, then
  `origin/$GITHUB_BASE_REF`, then `main`.
- Git and Buf commands continue to use argument-based process execution with
  no shell.
- Blocking tests cover PR, push/local, missing-ref, no-baseline, pass, and
  breaking-change behavior.
